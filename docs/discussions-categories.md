# Categorías de Discussions

GitHub no permite crear categorías de Discussions por archivo ni por API pública estable: se crean a mano en Settings, General, Features, Discussions (Set up discussions), luego Edit categories. Estas son las del equipo. Un issue es para trabajo concreto; una discusión es para hablar antes de que haya trabajo.

| Categoría | Formato | Para qué | Cuándo pasa a issue |
|---|---|---|---|
| Anuncios | Announcement (solo mantenedores publican) | Metas, fechas, lanzamientos | Nunca |
| Ideas | Open-ended | Mecánicas, contenido, "¿y si...?" | Cuando se decide hacerla: se convierte en issue con "Create issue from discussion" |
| Preguntas | Question and answer | Cómo se hace algo, dudas de Studio o Git | Si la respuesta es un cambio |
| Arte y mapa | Open-ended | Referencias, gustos, críticas del estilo low poly | Cuando hay un modelo o zona concreta por hacer |
| Resultados de pruebas | Open-ended | Qué se vio al jugar: dónde se aburre, dónde se traba | Cada bug o brecha concreta |

Regla: si alguien pregunta "¿quién hace esto?", es un issue con dueño. Si pregunta "¿esto está bien?", es una discusión.
